## 工具与环境坑（本会话实测）

- **deck_*** 工具走 `run_code` 内 `await tools.xxx()`；`deck_context` 必须传 `{}`（空参会被判 lossless JSON 失败）。`deck_issue_list` 的 `text` 只有计数，**行数据在 `.data.issues`**；`deck_issue_get` 的正文在 `.data.ticket.body`，edges 在 text 摘要里（"被阻塞 N 条"）。
- **ask_user_question 会超时**（120s 默认/600s 上限，YG 不点结构化卡片）。**有效做法：grilling 问题用聊天正文排版（❓Q1…➡️推荐），YG 直接键入「1.A 2.A…」回答**。等待期间可把问题先落档到票评论。
- **Windows shell 无 ls/find/head**（cmd 环境）——文件操作一律用 Node `fs`（readdirSync/readFileSync）或专用工具；git 命令正常可用。
- deck patch map body 是整体替换：改地图前必须**现读现改**（并发会话可能在编辑）。
- `reference/` 与 `.scratch/` 均 gitignored；本会话未改动它们（本交接文件也在 .scratch 下）。
