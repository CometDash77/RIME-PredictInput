## 6. 环境与工具坑

- `pnpm verify`：`tsc -p tsconfig.json --noEmit && tsc -p tsconfig.test.json --noEmit && vitest run`；单文件用 `pnpm exec vitest run tests/<file>`。**tsconfig 覆盖不到 `.scratch/`**，探针测试放 `tests/` 下。
- 仓库 `core.autocrlf` 生效，`git add` 时常打 `LF will be replaced by CRLF` 警告，正常，不是问题。
- **`git add` 的 pathspec 只要有一条不存在，整条命令 fatal 中止**，其余路径不会 staged；随后 `git commit` 可能只提交先前已 staged 的部分（本次的 `5f7dcac` 就是这么来的：只带走了 `git mv` 早已 staged 的 rename）。列路径前先确认文件存在。
- `gh issue view <n> --jq '<复杂表达式>'` 在 pwsh 里可能静默失败（exit 1、stdout 空）；稳妥写法：`gh issue view <n> --json body --jq .body | Out-File -Encoding utf8NoBOM .scratch/issue<n>-now.md` 再读文件。注意 PS5 的 `-Encoding utf8` 会带 BOM，读回来要 `replace(/^\uFEFF/,'')`。
- 写票/地图正文：先 `gh issue view` 存原文到 `.scratch/`，改完再 `gh issue edit --body-file`，然后**再取一次正文做逐字节比对**，确认只有目标行变了。
- vitest 被中断会在 `tests/` 留下 `.<testfile>.tmpdir/` 残留，收口时要清。
- 本机**没有真 Lua 解释器**，Lua 一律走 `wasmoon` 支架（`tests/support/lua.ts`）。已知 Lua 怪癖：`{n}` 重复量词在 Lua 模式里**不可用**；Lua 表 vs JSON 数组桥接时不要塞 null 值；组 Lua 表要用 `table.insert`/`ipairs`。
- 时间长了没输出的命令可以放后台（`run_in_background`），但**任务完成前必须读回结果**。
