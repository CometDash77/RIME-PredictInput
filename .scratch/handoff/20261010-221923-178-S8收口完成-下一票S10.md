## 7. 环境坑（已实测，照做即可）
- issue 读写：`gh issue view <n> --json body --jq .body | Out-File -Encoding utf8NoBOM <file>` → 改文件 → `gh issue edit <n> --body-file <file>` → 回读逐行比对（Node 里 `join("
")` 后 `replace(/s+$/,"")` 再逐行 diff）。PS5 `-Encoding utf8` 带 BOM；`gh issue view <n> --jq "<复杂表达式>"` 在 pwsh 静默失败；`deck_issue_get` 只回 stub，别当正文源。
- **`gh api repos/.../issues/1`（不带 `--jq`）会打印整份 issue JSON**，把 16K 字符的地图正文灌进上下文 —— 一律带 `--jq` 或只取所需字段。列子票：`gh api "repos/.../issues/1/sub_issues?per_page=100" --jq .[].number`；取 database id：`gh api repos/.../issues/<n> --jq .id`。
- **`git add` 只要有一条 pathspec 不存在，整条命令 fatal 中止**，随后的 commit 可能只提交先前已 staged 的部分（仓库历史 `5f7dcac` 就是这么产生的）。
- `--add-assignee "@me"` 必须带引号；gh 偶发 TLS timeout，重试即可。
- `tools.write` 的 content 用 JS 模板字面量时，正文里的 `${...}` 会被当插值 → `ReferenceError`；改用普通单引号字符串（反斜杠双写）。
- `run_code` 里 `const x: [string,string][] = [...]` 这类元组类型标注报 `Expected "," got ";"`；改用无标注数组 + function 表达式。
- `tools.pwsh` 的 command 里传 PowerShell 反引号会撑破 JS 模板字面量；`tools.read` 的 limit 上限 20000。
- 写文件用 `\` 哨兵技巧：内容拆成单引号字符串数组 `join("
")`，路径分隔符写 `\`，最后 `.split("\").join("\\")` —— 避免手工转义出错。
- tsconfig 不覆盖 `.scratch\`（探针测试放 `tests\` 并记得删）；仓库 `core.autocrlf` 生效（别用 clone 后的行尾比 sha256）；vitest 被中断会留 `tests\.<testfile>.tmpdir\` 需清。
