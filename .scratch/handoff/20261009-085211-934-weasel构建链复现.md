## 当前卡点（按优先级）

### 卡点 1：boost ARM32 缺 5 库 → 主构建 ARM 段 LNK1104

主构建输出：`LINK : fatal error LNK1104: 无法打开文件"libboost_wserialization-vc142-mt-s-a32-1_84.lib"`（WeaselTSF/WeaselIME ARM 平台）。

诊断中事实：

- bin.v2\libs\filesystem\build\msvc-14.2\ 下只有 address-model-32（x32）、architecture-arm（a64）、默认（x64）三种组合；**arm+address-model=32 组合只有 chrono/regex/serialization/system/thread 五库产出**。
- 已纠正的错误：`--with-wserialization` 是非法 b2 选项（error: wrong library name），wserialization 随 --with-serialization 的 complete 变体产出。
- 最后一次诊断动作：前台跑 `b2 --with-filesystem architecture=arm address-model=32 toolset=msvc-14.2 link=static runtime-link=static variant=release stage -a -d1`，**返回空输出且 exit 0**（异常：-a 强制重编应有编译输出）。接手者第一步：重跑该命令并把 stdout+stderr 都落文件检查（或加 -d2）；再查 bin.v2 是否新增 arm+32 产物。
- 可能原因（未证实，勿猜死）：ARM32 交叉编译需要 vcvars -arch=arm 环境（ARM64 是 cl /arm64 开关可无环境编，ARM32 没有等价开关，必须 HostX64\arm\cl.exe 进 PATH 或 vcvars）；或 b2 msvc-14.2 对 arm+32 组合静默跳过。对照上游：CI windows-2019 runner 镜像全组件，`build.bat boost arm64` 一次成功。
- 快速验证路径：cmd 里先 `call "C:\Program Files (x86)\Microsoft Visual Studio\2019\BuildTools\VC\Auxiliary\Build\vcvarsall.bat" x64` 或直接把 `...\VC\Tools\MSVC\14.29.30133\bin\HostX64\arm` 加入 PATH 再跑 b2 ARM32 段。
