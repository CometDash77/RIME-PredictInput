## 7. 环境坑（本会话新踩到的，接上 S8 交接档 §7）
1. **测试夹具是生成物**：`tests/release-repo-fixture.ts`（约 760 KB，内容取自真实工作树）由 `node tools/release/export-fixture.mjs` 导出。改了下列任一项后**必须重跑导出**，否则 `tests/release-gate.test.ts` 的「夹具同形」测试会红：`README.md`、`LICENSE`、`THIRD-PARTY-NOTICES.md`、两份 Release notes 模板、`src/eval/samples.ts`、`eval/README.md`、凭据基线文件、边界文件、`src/release` 里的路径常量。导出脚本从 `dist/release/*.js` 读判据常量，所以**先 `pnpm build` 再导出**。
2. **`dist/release-archive/` 与 `dist/release/` 分工**：前者放报告，后者放发布物。报告不要再写回 `dist/release/`——那样每次 `check` 都会把上一次的报告当「未声明条目」挡下自己。
3. **许可证正文的字节**：`.gitattributes` 里 `LICENSE -text` 与 `docs/license/*.txt -text`；正文按逐字比对，CRLF 转换会让别的机器上判据失败。取正文用 `[System.IO.File]::WriteAllText(..., UTF8Encoding($false))` 或 Node 写，别用 `Set-Content -Encoding utf8`（带 BOM）。
4. **Windows 的 Node 安装包不含 `LICENSE`**（`C:\Program Files\nodejs\` 只有 node.exe 与 npm 脚本）——内嵌运行时正文必须归档在仓库里，不能从本机读。
5. **内存 FS 的路径归一**：`tests/release-fixtures.ts` 的 `normalize` 要吃掉 `./` 前缀（gate 用 `root="."`，读的是 `./x`），否则「文件读不到」的假红会绕掉一会儿。
6. `gh api` 一旦不带 `--jq` 就会把整份 issue JSON 灌进上下文；列子票要显式写 `?per_page=100`（默认 30，会被静默截断，看起来像「已全部关闭」）。
7. PowerShell `Out-File -Encoding utf8NoBOM` **仍会写成 CRLF**：`gh issue view ... | Out-File` 之后必须 `replace(/\r\n/g,"\n")` 再编辑（本会话踩过，报 `PROGRESS ANCHOR MISSING`）。
