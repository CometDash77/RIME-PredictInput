# ADR 0011：云端先行的候选选择路线（#39 路线重审）

- 状态：已采纳（2026-10-13，用户三问拍板：云端先行；延迟以实测云端为基线反推本地档位；位置偏置列为验收硬指标）
- 背景：六臂 eval 全败（CI run 38403158750），唯一不达标项 = beyond-page 命中率 0.04–0.16（门槛 0.6），
  机制/留空/传输错误全 0——协议 v2 与「候选进 prompt、响应枚举」已工作，瓶颈是本地 0.8B/2B 模型
  对深位候选的排序能力。真机体感同构：输出多为机械复读候选第一项，待消费字符超过 2 个时几乎必然
  复读第一项（位置偏置随候选窗加深而恶化）。用户判定最初技术路线（本地小模型选深位候选）选错，
  开发困难源于此；旧地图 #33 关闭，本 ADR 为新地图 #38 的路线决策。

## 决定

1. **云端先行**：主推理通道 = 云端 LLM，复用 ADR 0004 的四通道设计与凭据槽
   （openai-responses / openai-chat / anthropic / custom OpenAI 兼容），不新建 wire。
   在凭据配置齐全前 cloud 通道维持缺省关闭（0004 安全设计不变）；key 就绪后云端为
   首选通道，本地 Ollama 降级为离线回退。选择边界不变：模型只在候选集合内选择
   （候选词库先行），响应仍是协议 v2 的候选词枚举，词库外输出一律拒收留空。
2. **延迟预算以实测云端为基线**：以「打字空闲触发 + 云端端到端延迟实测值」为准，
   本地档位的延迟目标 = 云端实测值；云端路径先跑通量化，再谈本地小模型能否追平。
3. **位置偏置为验收硬指标**：判据新增两个指标并交给 #40 修订 threshold.json——
   (a) 按待消费长度分桶（1/2/3+ 字）的准确率；(b) 复读第一项率（输出=候选[0] 且
   第一项并非正确答案时计错误）。云/本地对比评测必须同时报告这两项。
4. **触发与成本控制**：沿用打字空闲触发（现 local_wait_ms 量级）+ 在途请求按最新
   前缀取消 + 结果缓存（0004 缓存键 state·candidates·backend:provider·modelIdentity
   沿用）。candidates_window（协议 v2 的 255 窗）是成本杠杆：先 255 实测命中率，
   数据支持时可降窗（64/96）压输入 token。
5. **提供商候选**（OpenAI 兼容优先，custom 通道可直连任何兼容端点）：
   - DeepSeek（deepseek-chat：价格最低档 + 提供商侧上下文缓存 + 国内直连）— 首选手测对象
   - Qwen / DashScope（OpenAI 兼容，qwen-turbo/plus 档）
   - GLM（GLM-4-flash 有免费档，兜底）
   价格量级参考（以厂商页面为准）：DeepSeek 输入约 ¥1–2/M（缓存命中再低约一个量级）、
   输出约 ¥8/M 内；Qwen-turbo 同量级；单次请求输入 ≈ 系统+查询骨架 + 候选窗
   （255 词 × 2–4 token ≈ 700–1000 token），经空闲触发与缓存后日常成本可控。
   最终选型以用户 key 实测（延迟 + beyond-page 命中 + 复读率）后定档。

## 比较表

| 路线 | 深位命中预期 | 延迟 | 成本 | 状态 |
| --- | --- | --- | --- | --- |
| 本地 0.8B/2B（现状） | 0.04–0.16（实测） | 极低 | 0 | 已证伪（排序能力不足） |
| 本地 4B/8B | 未测 | 低 | 0 | 备选；预算按云端实测反推后再测 |
| 云端 API | 未测（预期显著更高） | RTT+TTFT 为主 | 按量，量级见上 | **主路线，先行实测** |
| 统计/规则重排 | 词频上限受限 | 极低 | 0 | 无语义能力，仅作兜底叠加 |
| 云端排序 + 本地兜底 | 高（在线）/本地回退 | 混合 | 中 | 云端跑通后的增强形态 |

## 后果

- 需要用户提供云 API key（settings cloud 槽，ADR 0004 ②A 已设计）；第一实测目标
  deepseek-chat：端到端延迟、beyond-page 命中、复读第一项率。
- 隐私告知义务：云端开启后，候选词（可能含用户词库与个人词条）会发送给提供商——
  设置页与文档须明示。
- 未提交的本地 WIP（src/eval/rig.ts +82：v3 评测臂候选窗 candidates_window、
  QUERY_JSON_SENTINEL 运行时同形查询；src/contracts/generation.ts +83：协议 v2 注释
  与查询对象共用）归属 #40 处置：作为判据修订与云/本地对比评测的现成基座，先行
  核验 rig.ts:382-385 per-schema 指标疑似 bug 后合入。
- ADR 0007 的 VALIDATED_GENERATION_* 显式赋值流程不变：云端组合达标后按同一机制
  放行，不因换通道而走判定捷径。
